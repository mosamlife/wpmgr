# WPMgr Outcome-Test Debt Register

## 1. Summary

The debt is **not uniform** — it clusters in three places while the rest of the suite is genuinely strong (backup *capture*, restore *rollback/health*, RLS cross-tenant reads, billing gates, autologin, password policy, 2FA *enrollment*, and the mu-plugin WAF gate all assert real outcomes). The false-greens concentrate at exactly the boundaries #170 warned about: **(a)** agent code paths that terminate in `exit()/wp_die()/require()` (hide-login block/serve, `onAuthenticate` brute-force tree, steady-state 2FA verify, hardening runtime callbacks) tested by asserting a *helper in isolation* or that a *branch was "reached"*; **(b)** the entire **forward restore path** (`stage()`+`swap()`, `preserveFromLive`, `DbRestorer::restore`) which no test ever drives to a successful Completed restore; and **(c)** the **whole web tier**, which by construction has *no* component-render testing (`@testing-library/react` is deliberately not installed) so every user-facing panel is covered only by extracted pure functions. The single worst pattern is `internal/auth/twofa_security_test.go`, whose "security-review gate" tests re-implement the guard as an inline `==` on two constants and never call the handler — a stub that deleted the check would stay green.
